# UC04 - Validar e finalizar o sistema

> **Jornada priorizada:** realizar a validação final do SGV, corrigindo problemas identificados e garantindo que as funcionalidades desenvolvidas estejam integradas e prontas para a entrega.

| Elemento | Definição |
|---|---|
| **Ator principal** | Gestor |
| **Objetivo** | Validar o funcionamento das principais funcionalidades do sistema e garantir sua estabilidade para a entrega final. |
| **Prioridade** | Alta |
| **Valor entregue** | O sistema passa por uma validação final, com correção dos problemas identificados e consolidação da versão de entrega. |

---

## Contexto da jornada

Após o desenvolvimento das funcionalidades previstas nas sprints anteriores, torna-se necessário realizar uma validação geral do SGV. Nesta etapa, são verificados os principais fluxos do sistema, a integração entre seus componentes e o comportamento das funcionalidades implementadas.

Os problemas identificados durante essa validação são corrigidos antes da consolidação da versão final do sistema.

> **Validação realizada:** as principais funcionalidades do sistema são verificadas antes da entrega, garantindo que os componentes estejam funcionando de forma integrada.

> **Objetivo da Sprint 4:** finalizar o desenvolvimento do SGV, corrigir bugs, validar as funcionalidades e preparar o sistema para a entrega final.

---

## Pré-condições

| Condição | Responsável |
|---|---|
| As principais funcionalidades do SGV estão implementadas. | Equipe |
| O ambiente do sistema está disponível para execução. | Equipe |
| O código das funcionalidades desenvolvidas está integrado ao projeto. | Equipe |
| A documentação do projeto está disponível para revisão. | Equipe |

---

## Fluxo principal

| Etapa | Ação | Resultado esperado |
|---|---|---|
| **1** | O gestor inicia a validação da versão atual do sistema. | O sistema é disponibilizado para verificação. |
| **2** | O gestor executa os principais fluxos das funcionalidades. | As funcionalidades são verificadas em condições de uso. |
| **3** | O sistema apresenta os resultados das operações realizadas. | Os comportamentos esperados são confirmados. |
| **4** | São identificados possíveis erros ou inconsistências. | Os problemas encontrados são registrados para correção. |
| **5** | A equipe realiza as correções necessárias. | Os problemas identificados são corrigidos no código. |
| **6** | Os fluxos afetados pelas correções são executados novamente. | As correções são validadas sem comprometer as funcionalidades existentes. |
| **7** | A documentação do projeto é revisada e atualizada. | As informações referentes ao sistema ficam consolidadas. |
| **8** | A versão final do sistema é consolidada. | O SGV fica preparado para a entrega final. |

---

## Tratamento de exceções

| Código | Situação identificada | Resposta esperada do sistema |
|---|---|---|
| **FA01** | Uma funcionalidade apresenta comportamento inesperado durante a validação. | Registrar o problema para análise e realizar a correção necessária. |
| **FA02** | Uma correção provoca impacto em outra funcionalidade. | Reavaliar a alteração e corrigir o impacto antes da consolidação da versão final. |
| **FA03** | O sistema apresenta falha durante a execução dos fluxos. | Identificar a causa da falha e realizar os ajustes necessários antes da entrega. |
| **FA04** | A documentação apresenta informações desatualizadas. | Revisar e atualizar a documentação antes da finalização do projeto. |

---

## Resultado da jornada

Após a conclusão do fluxo principal, as funcionalidades do SGV são validadas, os problemas identificados são corrigidos e a documentação é finalizada. O código e os demais artefatos são então consolidados para representar a versão final do sistema.

```text
Validação → Identificação de problemas → Correção → Nova validação → Documentação final → Entrega do sistema
