# Sprint 0 — Preparação

## Objetivo

A Sprint 0 prepara o ambiente de estudo de Docker, Spring Boot e React e organiza o repositório e o Kanban do projeto. Os artefatos de viagens usados nesta etapa são exemplos preparatórios; os requisitos definitivos do Sistema de Gestão de Viagens serão refinados com o Product Owner a partir da Sprint 1.

## Período acadêmico

| Início | Término | Estado inicial |
|---|---|---|
| 17 de agosto de 2026 | 24 de agosto de 2026 | Em andamento |

## Entregas

| Entrega | Issue Jira | Critério de verificação |
|---|---|---|
| Configuração do projeto Jira e quadro Scrum | ES2-2 | Backlog, fluxo e Sprint configurados no board do projeto. |
| Workspace GitHub e regras de contribuição | ES2-3 | Repositório privado confirmado, regras de contribuição publicadas e evidência de acesso adequado. |

| Containerização do exemplo de arquitetura | ES2-7 | Arquivos de containerização e instruções de execução validadas. |
| Checklist de entrega da Sprint 0 | ES2-8 | Checklist preenchido com links para todas as evidências. |

## Evidências aceitas

A conclusão de uma issue da Sprint 0 exige pelo menos uma evidência verificável associada ao trabalho realizado. São evidências válidas:

- arquivo versionado no repositório;
- commit ou pull request relacionado;
- instrução de execução validada;
- checklist preenchido;
- link de recurso técnico registrado na issue do Jira.

Não use commits vazios, links temporários ou documentação de outro projeto como evidência de entrega.

## Encerramento da Sprint

Antes de encerrar a Sprint 0, confirme que cada item possui evidência suficiente e que os artefatos não apresentam como requisitos definitivos elementos que ainda dependem do Product Owner.
